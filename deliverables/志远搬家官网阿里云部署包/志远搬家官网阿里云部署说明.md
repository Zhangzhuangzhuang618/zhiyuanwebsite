# 志远搬家官网：阿里云部署说明

适用范围：当前 `zhiyuanwebsite` Git 仓库与本压缩包内的实际配置、网站数据库。

## 1. 压缩包内容

本压缩包包含以下未提交到 Git 仓库的实际运行文件：

- `app/config/site.php`：网站域名、后台账号密码哈希、SQLite 路径等实际配置。
- `data/demo.sqlite`：当前新闻、案例、网站内容、后台数据和留言。
- 本说明文件。

> `site.php` 和 `demo.sqlite` 含真实业务数据，不能提交到公开 Git 仓库。请仅通过受控账号上传、备份和保管。

## 2. 服务器要求

- Nginx
- PHP-FPM：建议 PHP 8.1 或 PHP 8.2（项目最低要求为 PHP 7.3）
- Composer
- PHP 扩展：`pdo_sqlite`、`sqlite3`、`mbstring`、`fileinfo`、`gd`、`openssl`
- 阿里云安全组和服务器防火墙均需开放 TCP `80`、`443`

网站使用 SQLite，不需要新建 MySQL 数据库。

## 3. 上传实际配置和数据库

假设项目已通过 Git 拉取到：

```bash
/var/www/zhiyuanwebsite
```

解压本压缩包后，覆盖服务器项目内的同名文件：

```text
app/config/site.php
data/demo.sqlite
```

注意：

- 如果服务器已有新的后台数据，请先备份原 `data/demo.sqlite`，再覆盖。
- 不要删除 `public/upload/`，该目录保存历史图片及后台上传图片。

## 4. 安装 PHP 依赖

在项目根目录执行：

```bash
cd /var/www/zhiyuanwebsite
composer install --no-dev --optimize-autoloader
```

不要使用 `composer update`，避免意外升级依赖版本。

## 5. 设置写入权限

SQLite 数据库、运行缓存和后台图片上传目录必须对 PHP-FPM 用户可写。

Ubuntu 通常使用 `www-data`：

```bash
cd /var/www/zhiyuanwebsite
chown -R www-data:www-data data runtime public/upload
chmod -R 775 data runtime public/upload
```

CentOS/RHEL 可能使用 `nginx` 或 `apache` 用户，应按实际 PHP-FPM 运行用户替换。不要设置 `777` 权限。

## 6. Nginx 配置

Nginx 的 `root` 必须指向项目内的 `public/`，不能指向项目根目录。

```nginx
server {
    listen 80;
    server_name zhiyuanbj.cn www.zhiyuanbj.cn *.zhiyuanbj.cn;

    root /var/www/zhiyuanwebsite/public;
    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    location ~ /runtime/ { deny all; }
    location ~ /\. { deny all; }
}
```

将 `/var/www/zhiyuanwebsite` 换成服务器真实路径；`fastcgi_pass` 中的 PHP-FPM Socket 也应按实际 PHP 版本修改。

项目自带的 `nginx.conf` 中有两行 `server_name`，生产环境请合并为上例中的一行。

## 7. DNS 与 HTTPS

需要在 DNS 服务商处添加以下 A 记录，均指向服务器公网 IPv4：

| 主机记录 | 用途 |
| --- | --- |
| `@` | 主站 `zhiyuanbj.cn` |
| `www` | `www.zhiyuanbj.cn` |
| `*` | 广州各区等子站点 |

泛域名记录不能省，否则各城市/区域子站无法访问。

DNS 生效后申请 HTTPS 证书，并配置 HTTP 301 跳转到 HTTPS。证书需要覆盖主域名、`www` 和泛域名；也可以分别申请。

## 8. 上线验证

1. 打开 `https://zhiyuanbj.cn/`，确认样式、图片和视频正常。
2. 打开 `https://zhiyuanbj.cn/webadmini/login`，确认后台能登录。
3. 在后台新增或编辑一条资讯，确认封面图能上传并正常展示。
4. 检查报价弹窗、验证码、在线客服拨号及留言提交。
5. 访问任意城市子域名，确认泛域名解析已生效。
6. 查看 Nginx 和 PHP-FPM 错误日志，确认未输出 PHP 报错。

## 9. 后续更新和备份

- 更新代码：先备份，再执行 `git pull`；如依赖文件有变化，再执行 `composer install --no-dev --optimize-autoloader`，随后重载 PHP-FPM 和 Nginx。
- 备份数据：定期备份 `data/demo.sqlite`、`app/config/site.php`、`public/upload/`。
- 数据库使用 SQLite。复制 `demo.sqlite` 时避免后台同时大量写入，防止备份不完整。
- 不要将服务器上的 `site.php` 和 `demo.sqlite` 推送到公开仓库。

## 10. 常见问题

| 现象 | 优先排查 |
| --- | --- |
| 502 Bad Gateway | PHP-FPM 是否启动；Nginx 的 `fastcgi_pass` Socket/端口是否正确。 |
| 首页 404 或路由失效 | Nginx 的 `root` 是否指向 `public/`；是否配置 `try_files`。 |
| 后台上传失败 | `public/upload/` 是否可写；`fileinfo` 扩展是否启用。 |
| 数据库报错或内容丢失 | `data/demo.sqlite` 是否已上传；`data/` 是否可写；是否启用 `pdo_sqlite`。 |
| 城市子站打不开 | `*.zhiyuanbj.cn` 的 DNS A 记录和 Nginx 的泛域名 `server_name` 是否已配置。 |
